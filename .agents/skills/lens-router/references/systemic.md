# Systemic Lens

## Purpose

Inspect how parts of the object interact over time, how local changes affect
larger state, where feedback or recurrence exists, and which constraints shape
future behavior.

Core question: **How does what happens here change what can happen elsewhere or
next?**

## Investigation

Start from observed or specified interactions. Do not assume feedback,
hierarchy, equilibrium, or causal influence merely because systems vocabulary
makes those ideas available.

Ask:

- What state is relevant, and what can change it?
- What constrains or blocks those changes?
- What happens downstream when a local unit changes?
- Can local work close, open more work, invalidate a premise, or change the
  route?
- Where does locally produced information or evidence become globally relevant?
- What persists across iterations, and what is reset or recomputed?
- Is there feedback? What exactly returns to what, under which condition?
- What are the stop or closure conditions?
- Which interactions are guaranteed, optional, or proposed?
- Where can drift, accumulation, bottlenecks, or coordination overhead arise?
- What action changes the system rather than merely observing it?

Use distinctions only when they clarify actual behavior:

- state versus event;
- local versus global;
- input versus consequence;
- observation versus intervention;
- open-loop versus feedback behavior;
- dependency versus temporal order;
- closure versus recurrence;
- bottleneck versus blocker;
- persistent state versus transient output.

## Forbidden jumps

Do not infer:

- feedback because a process repeats;
- causality because one event follows another;
- global improvement from local success;
- equilibrium or stability without evidence;
- a linear pipeline when work can branch, recur, or recompose;
- system ownership from information flow;
- authority flow from dependency or control flow.

## Return

Return a few load-bearing findings covering:

- relevant state and interactions;
- local-to-global effects;
- supported feedback or recurrence;
- constraints and stop conditions;
- uncertainty about dynamics;
- questions whose answers would change the system model.

Write concise analysis notes that preserve the evidence basis and uncertainty.
Prefer mechanism over component enumeration, and do not discard distinctions
needed downstream.
