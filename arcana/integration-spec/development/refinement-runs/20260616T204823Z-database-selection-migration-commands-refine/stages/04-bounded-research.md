# Bounded Research: Data Stores And Migration Commands

Status: pass
Owner capability: refine
Research mode: bounded-research

## Data Store Research

| Source | Finding | IntegrationSpec implication |
| --- | --- | --- |
| AWS Well-Architected purpose-built data store guidance | Storage should support workload querying, scaling, storage, use cases, and data models. | Selection record starts with workload/access/data model, not vendor preference. |
| Azure data store preparation guidance | Applications and services should document storage and access requirements before selecting supported resource types. | Require explicit access and governance fields before technology choice. |
| Azure data model guidance | One store rarely satisfies every access pattern efficiently; model families include relational, key-value, document, graph, time-series, object, search, vector, and analytics. | IntegrationSpec should model resource family and authority role, including polyglot boundaries. |

## Migration Command Research

| Source | Finding | IntegrationSpec implication |
| --- | --- | --- |
| Flyway migrations | Migrations are versioned/repeatable artifacts tracked in schema history; dry-run/drift reports can be reviewed before deployment. | Require migration artifact identity, history state, drift check, and dry-run evidence. |
| Flyway repair | Repair realigns schema history, checksums, descriptions, and missing migrations. | Treat repair as exceptional migration-truth mutation requiring a gate. |
| Liquibase update and lock docs | Update compares changeset identifiers and checksums; lock table serializes concurrent updates. | Require checksum policy and lock policy. |
| Liquibase update-sql | SQL can be generated for review before applying changes. | Model dry-run/review output as an evidence fixture. |
| Prisma Migrate | Commands separate development and production/staging; production commands use advisory locking. Reset is development-only and destructive. | Require environment command policy and block destructive commands in production by default. |
| Alembic and Django | Generated/autogenerated migrations and SQL plans are candidates or previews that still need review. | Generation does not equal approval; review evidence is separate from apply evidence. |

## Research Decision

The evidence supports an L0 Integration Boundary Discipline section with two records: data-resource decision and migration-command profile. Live database command proof is deferred.
