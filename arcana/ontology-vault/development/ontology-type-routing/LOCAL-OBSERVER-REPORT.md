## Observer Inference

- Existing branch selection distinguishes business, system, and bridge scope,
  but it does not identify the ontology's primary modeling job.
- `system` alone is under-specified: a runtime topology and an architecture
  property schema are both system-facing while requiring different concepts,
  relations, evidence, and outputs.
- A small routing catalog can prevent recurrence if it remains a selection aid
  and does not absorb project-local ontology names.
- The gap affects process, Quality Bar, Anti-Patterns, output contract, runtime
  profiles, and observability. A README-only clarification would not be enough.

## Recommendation

Reflection trigger: `manual`

Severity: medium

Recommendation: targeted update

Required changes:

1. add a reusable ontology type catalog;
2. resolve explicit, profile, inferred, and user-selected routes in precedence
   order;
3. distinguish architecture properties from system runtime and cross-branch
   traceability;
4. preserve branch arguments as traversal controls;
5. report selection evidence and ambiguity;
6. add repeatable routing fixtures.
