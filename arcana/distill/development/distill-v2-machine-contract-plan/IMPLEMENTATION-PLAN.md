## Implementation Rules

- Every SWU consumes exact predecessor receipts and a fresh target baseline.
- Schemas are Draft 2020-12, closed by default, and use repository-resolvable `$ref` values.
- Producers stage a complete output family in a sibling temporary directory,
  validate there, then publish atomically. Failure leaves the prior family unchanged.
- The semantic finalizer validates, binds, renders, and inventories. It cannot
  invent Proposer/Balancer claims, resolve tensions, or choose a verdict.
- Modes and techniques are independent machine instances. Profiles contain exact
  refs plus selection policy; they do not fork those definitions.
- Old Invoke adapters are compatibility-read evidence only until their owner
  accepts a versioned projection. New v2 writers emit only the selected canonical vocabulary.
- Human Markdown and generated native packages are deterministic projections of canonical machine bytes.
- Exact allowlists are used for validation and eventual Git staging; unrelated dirty bytes are never absorbed.

## Compatibility And Rollback

- Add v2 beside existing adapters; do not mutate historical schema semantics in place.
- Preserve old hyphenated technique labels only in a tested compatibility mapper
  if the selected decision permits it; canonical v2 instances remain underscore IDs.
- Each SWU is revertible at its declared write boundary. Atomic publication keeps
  the previously valid contract family when candidate validation fails.
- A changed accepted schema, profile, mode, technique, producer, or validator byte
  creates a new exact candidate and invalidates downstream receipts.
