## Layer 0: Define Handoff

Decision question:

```text
After this layer, we know whether the sigil concept is coherent enough for sigil-development.
```

Included:

- Sigil handoff with identity, purpose, IO, modes, interaction contract, runtime expectations, observability, and validation examples.
- Budget profiles, objective-output artifact confirmation, output contract, technique pack contract, navigation closeout, and Balancer objection categories.
- Local glossary for candidate concept terms.
- Define transport notes.
- Literature research addendum.
- Interrogation review confirming design readiness for sigil-development.

Deferred:

- README.md and SKILL.md creation.
- Runtime adapter wiring.
- Registry updates.
- Validation fixture execution.

Exit evidence:

- invoke define gate passes for the sigil handoff.

## Layer 1: Candidate Sigil Package

Decision question:

```text
After this layer, we know whether the sigil can be executed manually from README.md and SKILL.md.
```

Included:

- arcana/distill/README.md
- arcana/distill/SKILL.md
- compact, standard, tournament, deep, and validate mode definitions.
- budget override rules, final result schema, and readiness verdict rules.
- objective-output artifact pair confirmation and revision rules.
- discovery baseline rules for evidence, blocker unknowns, non-blocker unknowns, and assumptions.
- navigable result check and final navigation guide.
- technique pack execution rules and role trace expectations.
- mode/technique surface interfaces from arcana/distill/development/MODE-TECHNIQUE-SURFACE-DESIGN.md.
- detailed technique contracts from arcana/distill/development/techniques/README.md.
- quality bar, anti-patterns, output contract, and handoff routes.

Deferred:

- Runtime command adapter.
- Registry promotion.
- Automated telemetry scripts.
- Formal code-level state schemas for ModeProfile and TechniqueSpec.

Exit evidence:

- Manual review confirms first-turn intent/budget confirmation, finite recursion, closure test, technique pack execution, output contract, and cycle guards.

## Layer 2: Validation And Examples

Decision question:

```text
After this layer, we know whether the sigil behaves consistently across small, broad, and contested planning problems.
```

Included:

- Passing examples for Standard and Tournament modes.
- Negative examples for infinite reduction, premature complexity, lost recomposition, brittle minimalism, excessive cognitive load, and unsupported tournament convergence.
- Technique-specific examples for recomposition proof, evolution profile, cognitive load check, requisite variety check, boundary-object check, concept-vs-knowledge status, premortem pass, and set-based tournament.
- Examples where the expected output artifact changes after discovery, and examples where a result is downgraded until it includes a navigation guide.
- Validation notes for role simulation fallback.

Deferred:

- Full observed invocation integration.

Exit evidence:

- Examples show expected pass, flag, and block outcomes.

## Layer 3: Runtime And Observability

Decision question:

```text
After this layer, we know whether the sigil can be invoked from the local command surface and observed after meaningful use.
```

Included:

- Codex command adapter.
- Observability signals for budget selection, reduction rounds, technique pack passes, closure tests, premortems, cycle guards, and optimization point selection.
- Reflection trigger thresholds.

Deferred:

- Canonical registry promotion until repeated use validates behavior.

Exit evidence:

- Command resolves through tools/arcanum.
- Observability closeout records a representative run.

## Layer 4: Registry Candidate

Decision question:

```text
After this layer, we know whether Distill should become a listed reusable sigil.
```

Included:

- registry/SIGILS.md candidate entry.
- Link validation.
- Promotion decision record.

Deferred:

- Any global definition promotion for candidate glossary terms.

Exit evidence:

- Sigil-development validation passes and the user approves registration.
