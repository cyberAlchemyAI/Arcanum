# Dispatch Technique Trace

## Route

```text
Invoke package
  -> Sigil Development lifecycle decision
  -> Task Session L0 contracts
  -> Task Session L1 mechanism
  -> Task Session L2 owner integration
  -> Signal Observer
  -> Experiment Harness pilot verdict
```

## Techniques

| Technique | Use |
| --- | --- |
| `sequence` | shared-path and contract dependencies require ordered waves |
| `artifact_contract_bridge` | every owner boundary crosses with a versioned artifact |
| `execution_receipt_handoff` | no phase advances on prose completion |
| `concrete_path_evidence` | every SWU has an exact write and evidence inventory |
| `scu_swu_reduction` | each SWU owns one independently verifiable behavior |
| `recomposition_proof` | W3 proves the complete path without erasing layer evidence |
| `validation_loop` | schema, adversarial fixture, regression, and experiment gates |
| `owner_boundary_check` | Task Session orders hooks but does not absorb owner semantics |
| `handle_handoff` | terminal continuity cursor returns a handle, not execution |
| `residue_ledger` | dirty-state, stale prose, and unproven speed remain explicit |
| `observability_grouping` | phase and hook evidence group under one run ID |

## Non-dispatch statement

The dispatch document validates capability sequencing. It does not authorize a
multi-agent execution. Any later governed fan-out requires a separately confirmed
DomainSpec strategy and registered dispatch.

Canonical skill/docs and generated mirror integration are deferred to a separate
post-pilot Sigil Development work pack.
