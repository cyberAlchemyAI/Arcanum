# Stage 06: Invoke Redefine / Design

Status: pass

## Design

The visual library should be documentation-first and validator-friendly.

Each component entry should include:

- component id,
- family: shape, connector, chart, or pattern,
- intended lane,
- purpose,
- inputs,
- SVG/HTML sketch or pseudo-markup,
- evidence rule,
- when not to use it.

Each pattern entry should include:

- pattern id,
- target modes,
- required lanes,
- recommended components,
- accessibility notes,
- validation notes.

The user-shapes template should ask for:

- shape name,
- target domain,
- lane served,
- source evidence it represents,
- visual sketch,
- anti-pattern warning.
