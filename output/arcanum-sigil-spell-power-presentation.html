01 / The triad

Each one answers a different question.

Refine

What are we really trying to shape?

Use it when the target is vague: a folder, design concern, rough product idea, architecture worry, or “this feels wrong.” It builds a seed, runs staged critique and repair, records evidence, and returns a final synthesis with next routes.

arcana/refinediscovery loop

Invoke

What artifact should represent this intent?

Use it when something needs to become a governed definition, design, plan, work-pack, handoff, or refresh report. It owns authoring outputs and routes the resulting artifact to the lifecycle owner.

spells/invokeauthoring spell

Distill

What is the smallest coherent unit?

Use it when the idea is too broad, overbuilt, underbuilt, or needs concept-layer optimization. It reduces, challenges, reconciles, and proves how the chosen unit recomposes into the larger design.

arcana/distillconcept optimizer

The short version: Refine is the loop, Invoke is the artifact author, Distill is the concept-pressure machine.

02 / Distill in detail

Distill finds the unit that is small enough to act on and large enough to still mean something.

Distill is for models, architectures, plans, workflows, and implementation shapes that feel too big to touch responsibly.

Its power is not “make it smaller.” Its power is selecting the smallest coherent unit with responsibility, inputs, outputs, a boundary, and a recomposition path.

Proposer Balancer Orchestrator recomposition proof
Distill asksWhy it matters
What broad concept layer contains this request?Prevents solving the wrong abstraction level.
Which smaller concepts must combine for it to work?Finds real parts instead of arbitrary fragments.
Where does splitting further remove meaning?Stops reduction before it creates hidden glue.
How does the selected unit recombine upward?Proves the unit can serve the larger design.
03 / Distill modes

Distill has different pressure settings.

Compact

Quick bounded pass.

One proposal track, one recursive round, and only the always-on gates. Good when the target is clear but needs a sanity-shaped optimization point.

Standard

Default serious planning.

One Proposer, one Balancer, two recursive rounds, and reconciliation. This is the normal “help me find the right shape” setting.

Tournament

Competing design tracks.

Several proposal tracks compete, each balanced, then an evidence-based pitch-off selects the best optimization point.

Deep

High-risk strategic work.

More rounds, cycle checks, premortem, triggered techniques, and stronger gates when the cost of choosing the wrong shape is high.

Validate

Critique an existing design.

Balancer-led review with optional repair. Useful when you already have an artifact and want to know if its unit boundary holds.

Result

A navigable optimization record.

Target context, chosen unit, concept layer map, technique trace, recomposition proof, deferred complexity, tension ledger, and next route.

04 / Invoke in detail

Invoke turns intent into governed authoring artifacts.

Invoke is a spell, not a single-purpose sigil. Its job is to discover intent, select the right authoring mode, produce structured artifacts, and hand off to the capability that owns the next lifecycle step.

Define

Create the authoring baseline.

Clarifies intent, chooses templates or recipes, creates a spec and glossary baseline, records unresolved gaps, and prepares downstream design.

Design

Turn definition into architecture.

Creates governed design artifacts, checks view coverage, aligns glossary meaning, and preserves design gates before plan work begins.

Plan

Create execution-ready planning.

Produces implementation plans, implementation layering, validation strategy, work-packs, and Smallest Working Units when complexity requires them.

Handoff

Split or continue work safely.

Builds a new session/thread handoff from a prompt, source session reference, and Context Builder selection instead of dumping a whole transcript.

Refresh

Update artifacts from new evidence.

Maps source signals to typed deltas, defaults to proposal-only, and treats no-op as valid when the latest evidence is already represented.

Ownership Boundary

Authoring is not lifecycle completion.

Invoke can author for a feature, sigil, spell, or module, but the target owner handles lifecycle mutation, validation, execution, and promotion.

05 / Invoke gates

Invoke is powerful because it refuses vague outputs.

GateWhat it protects
One-question clarificationPrevents broad interviews from drowning the user.
Template selection evidencePrevents arbitrary artifact shape choices.
Implementation layeringPrevents plans from mixing proof, pilot, scale, and polish.
Work-pack and SWU coveragePrevents vague task labels from becoming execution work.

Gap ownership splitSeparates Invoke flaws from target-artifact flaws.

Invoke’s output contract names mode, status, artifacts, design coverage, glossary consistency, implementation layering, work-pack shape, complexity, decisions, unresolved gaps, and next route.

This makes it excellent for demos: you can show not just the generated artifact, but the governance around why that artifact is ready, flagged, or blocked.

06 / Refine in detail

Refine is the front door for unclear targets.

Use Refine when the user points at a vague idea, folder, design concern, repository area, or rough plan and wants a real synthesis before implementation or lifecycle promotion.

SeedResolve the target, propose a refinement seed, and record what kind of output the loop should produce.
Research ModeChoose no-research, bounded-research, or research-if-gap-appears, with local evidence kept authoritative.
DispatchRun command-backed stages through the local Arcanum command surface and record each stage in a manifest.
SynthesizeCombine Context Builder, Invoke, Interrogation, and Distill outputs into a final refined result.
RouteRecommend the next owner: Invoke, Task Session, Sigil Development, Spellcraft, Decision Gate, or defer.

Refine does not pretend the first prompt is already the plan. It makes the plan earn itself through evidence, critique, repair, and route selection.

07 / Refine loop

The canonical refinement loop is a composed workflow.

1. Evidence Baseline

Context Builder gathers selected evidence and avoids whole-repo wandering. This gives the loop a source-backed starting point.

2. Invoke Define

Invoke creates a definition baseline so the loop has a concrete artifact to critique rather than only conversation residue.

3. Interrogation

Critique and readiness checks expose gaps, unresolved assumptions, and questions that matter before the design hardens.

4. Distill

Distill finds the coherent unit, records tensions, proves recomposition, and repairs overbroad or brittle designs.

5. Invoke Design And Plan

Invoke turns the repaired model into design, implementation layering, plan artifacts, and work-pack material.

6. Final Synthesis

Refine returns the run manifest, evidence index, result, stage outputs, blocked reasons, and recommended next route.

08 / Ownership chain

They compose without stealing each other’s job.

CapabilityOwnsDoes not own
RefineSeed design, research decision, stage dispatch plan, manifest/index, final synthesis, route recommendation.Direct implementation or lifecycle promotion.
InvokeDefinition, design, plan, work-pack, handoff, refresh artifacts, and artifact authoring gates.Target lifecycle completion, sigil mutation, spell mutation, or task execution.
DistillConcept-layer reduction, role critique, optimization point, recomposition proof, deferred complexity, next route.Writing the full plan or executing the selected unit.
Task SessionOne bounded execution task after artifacts and gates are ready.Vague discovery, broad design refinement, or concept optimization.

That boundary is the secret sauce: the trio can be powerful without becoming one giant “do everything” prompt.
