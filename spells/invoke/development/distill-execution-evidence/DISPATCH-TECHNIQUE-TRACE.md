# Dispatch Technique Trace

Full dispatch validation is required because the route crosses Invoke, Distill, Spellcraft,
runtime evidence, Task Session, observability, generated mirrors, and Workbench ownership.

| Technique | Applied To | Validation Expectation | Status |
| --- | --- | --- | --- |
| `sequence` | define -> design -> lifecycle acceptance -> implementation -> replay -> independent closeout | every step consumes a prior artifact or result | pass |
| `artifact_contract_bridge` | Distill output contract -> receipt/validator checks | every load-bearing output obligation has a validator check | pass |
| `execution_receipt_handoff` | runtime roles -> evidence validator | execution claims return resolvable receipt/event handles | pass |
| `concrete_path_evidence` | fixtures, generated mirrors, Workbench replay | claims cite concrete artifact paths | pass |
| `scu_swu_reduction` | work-pack decomposition | first selected unit is lifecycle acceptance only | pass |
| `recomposition_proof` | individual SWUs -> accepted architecture | each SWU maps to a design capability and final replay | pass |
| `validation_loop` | schema, semantic, adversarial, replay, and independent closeout validation | positive and negative evidence are explicit | pass |
| `owner_boundary_check` | Invoke -> Spellcraft/Sigil Development/Task Session | no artifact claims another lifecycle's authority | pass |
| `handle_handoff` | package and runtime evidence references | artifacts are passed by path/handle | pass |
| `residue_ledger` | unresolved architecture and replay gaps | each gap has an owner and repair route | pass |
| `observability_grouping` | run, role, validation, replay events | events share stable run and parent identifiers | pass |

Skipped:

- `anti_bias_vector_composition`: the Invoke authoring route does not create a qualifying
  `n >= 2` investigate/evaluate subject group. Distill role opposition is handled by its own
  runtime-role policy.
- `authority_split_gate`: `owner_boundary_check` plus the explicit Spellcraft gate is enough;
  no definition or ontology promotion is proposed.
