# Glossary

| Term | Status | Meaning or authority reference |
| --- | --- | --- |
| Invoke Plan | candidate | The checked map from an approved design to the exact work people or agents can perform next. |
| Plan authoring source | candidate | The one JSON file where the Plan is actually written; everything readable is generated from it and every later result points back to it. |
| Work Pack | candidate | The readable control panel for the Plan, generated from the real source rather than becoming another place to edit it. |
| Delivery slice | candidate | A meaningful piece of the result we can show, separate from the order in which we build it. |
| Implementation layer | candidate | A checkpoint in implementation where we answer one kind of question before taking on the next kind. |
| Plan wave | candidate | A batch of work that can proceed together after its prerequisites and before the next checkpoint. |
| Plan task | candidate | One responsibility in the plan, detailed enough that its smaller work units can be assigned and checked. |
| Smallest Working Unit | candidate | The smallest piece of work that can be assigned, completed, and proved correct on its own. |
| Implementation detail contract | candidate | The practical instructions that turn a task name into work someone can implement safely. |
| Validation obligation | candidate | The specific check and result we need before we can say a piece of the Plan worked. |
| Plan gate | candidate | A checkpoint that opens only when the exact proof it asks for is present and valid. |
| Plan blocker | candidate | A specific problem that must be fixed before this part of the Plan can move forward. |
| Plan gap | candidate | Something still missing that we can safely carry for now, with a named owner and a clear point where it would stop us. |
| Execution entry | candidate | The Plan defines which doorways into execution are allowed; a later receipt chooses the exact doorway and unit for this run. |
| Execution Pack | candidate | The coordination map for a larger Plan, showing what runs when without becoming a second set of task instructions. |
| Plan candidate bundle | candidate | All Plan files produced together from one source, held for checking before anyone treats them as accepted. |
| Plan bundle admission | candidate | A second checker proves that this exact generated Plan still matches its source and works with the checks that depend on it. |
| Plan evidence state | candidate | A precise answer to what we have proved about the Plan so far, without turning 'written' into 'ready' or 'approved.' |
