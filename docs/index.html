The method

Language becomes a way to build operational memory.

CyberAlchemy treats names, prompts, schemas, validations, and artifacts as working material. A good name is not decoration; it is a handle for a repeatable process.

name

Give the pattern a handle

Start with the messy thing you keep doing. Name it so it can be pointed at, improved, taught, and reused.

shape

Turn intent into artifacts

Use refine, invoke, guides, x-rays, work-packs, and task-sessions to make the idea inspectable before mutation.

prove

Keep evidence with the work

Every serious output should leave receipts: sources, decisions, validators, screenshots, residues, and the next route.

Arcanum loop

From a wild idea to a validated working slice.

1

Prompt

Describe the idea, user, promise, constraints, unknowns, and ambitious future.

2

Refine

Extract the core shape, compare routes, expose gaps, and choose the next owner.

3

Invoke

Author definition, design, layering, work-pack, and handoff artifacts.

4

Route

Use decision-gate, dispatch-spec, x-ray, or another refine pass when uncertainty appears.

5

Execute

Run one bounded task-session with validation and synchronized evidence.

6

Learn

Preserve residue, telemetry, follow-up gaps, and the next loop.

Arcanum directly

The repository is the working surface.

No separate static handoff is needed here. The public Arcanum system carries the real material: sigils, guides, validators, research traces, work-packs, and examples that can be inspected, reused, and improved.

Start here

Ask for the shape, not the implementation first.

The best first prompt is rich, unfinished, and honest about what is exciting, risky, unclear, and worth proving.

[$refine] I want to develop this idea:

Describe the product, audience, promise, current workflow, missing pieces, constraints, risks, unresolved decisions, MVP proof, and ambitious future.

Please refine this into definition, design, plan, gaps, blockers, and the next executable task.
