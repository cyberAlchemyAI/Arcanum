Who we are

We build systems for people — and the agents working alongside them.

Two builders working at the intersection of systems thinking, software design, and philosophy. We put the complexity into the structure, so the person using it does not have to carry it. None of this is theory we are selling — it is how we have watched good systems behave, and bad ones fail.

Why we build this way

A few convictions, learned the hard way.

variance lives somewhere

Fewer special cases

The good version of a system has fewer exceptions. We push them into the structure instead of leaving them for people to remember.

stress should make it better

Built for the rare, expensive surprise

The shocks come. We build so they do not break us — and so each failure becomes a rule the system now carries.

conditions, not commands

Set the conditions; let the right thing show up

Rigid rules break under reality. We shape the environment so the correct behavior emerges — for the humans and the agents both. A nudge, not a cage.

if it needs translating, it isn't done

A system should explain itself

A system that cannot be read concentrates power by hiding how it works. Ours should be legible to a person and to a machine, and say why it exists right where you meet it.

What we believe

Research is how you map an unknown domain. The software is just the instrument.

We treat research as the actual work: discovering and mapping a domain no one has charted yet. Any software we build is a tool for that discovery — not the point of it.

Code is not the end product. It is an observational probe — something we send into a domain to chart its territory, measure how it moves, and bring back evidence.

How we work

Cybernetics², applied to our own tools.

We research cybernetic theory — and then we apply it to the tools we build with it. The systems we make are cybernetic loops around human work: they track intent, interpret what reality did, check whether the two still agree, and feed that back to the people running the operation.

It is cybernetics turned on itself — a loop that watches a loop. The point is never to take the human out. It is to give the operator a sharper read on their own system.
