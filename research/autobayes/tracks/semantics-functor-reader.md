## Core Reading

AutoBayes treats everything before section 5 as compositional syntax for variational inference:

```text
open models
  -> Bayesian lenses / local inversions
  -> statistical games / local energy and entropy
  -> parameterized statistical games
```

Section 5 then asks for semantics: how a declared parameterized game gets an optimization behavior. The paper's analogy is explicit: an automatic differentiation system is incomplete without an optimizer, and AutoBayes likewise needs a way to optimize the loss functions generated by its compositional syntax.

The first source-level move is parameter exposure. A statistical game by itself has a loss, but it exposes no obvious parameter for an optimizer. AutoBayes therefore defines a parameterized statistical game as:

```text
(Theta, c)
```

where `Theta` is a parameter space and `c` maps each parameter value to a statistical game. Any part of the game may depend on the parameter: the forward model, inversion, energy, entropy, or distribution-family annotation.

This is the cleanest thing to keep for Arcanum: the optimizer does not get to touch arbitrary global state. It receives an explicitly exposed handle.

## What AutoBayes Proves Or Says

Source-backed claims from section 5:

1. Parameterized statistical games are the object that makes optimization meaningful. Without parameter exposure, there is a loss but no declared optimization handle.
2. Bayesian learning rule-style gradient descent is treated as the standard optimization semantics for AutoBayes when the parameter space is a statistical manifold with a Fisher information metric.
3. Composition of parameterized games is defined by producting parameter spaces and mapping parameter pairs into the composite statistical game.
4. Local gradients can be composed into a structured vector for the composite.
5. Strict functorial equality generally fails: the composed local-gradient expression is not, in general, equal to the gradient of the globally composite loss at the same points.
6. The failure is not treated as collapse. AutoBayes calls the gradient assignment lax, and says that this laxness can be accounted for mechanistically by an implementation.
7. Formally, parameterized statistical games form a monoidal bicategory; coupling parameter spaces to tangent bundles yields a fibration; gradient assignment is a lax section of that fibration.
8. The paper expects different optimization strategies to correspond to different "semantics functors": Laplace, delta rule, sampling schemes, and related gradient-estimation strategies are named as examples.

So the proved/stated structure is not "there is one optimizer." It is:

```text
declared parameterized game syntax
  -> local gradient data
  -> lax compositional assignment
  -> implementation-chosen semantics functor
```

## What Remains Implementation Strategy

AutoBayes explicitly leaves implementation of the framework for future work. Section 5 sketches the algorithmic pressure points rather than shipping an executable semantics.

Implementation-strategy items include:

- how to compute or approximate pushed-forward priors in composite games;
- when to use belief propagation or variational message passing;
- how to propagate information backward through posterior samples or posterior expectations;
- how to simplify computation under conjugacy;
- how to project pushed-forward priors back into required distribution families, such as by moment matching;
- how to annotate games with distribution-family predicates so an implementation can choose valid methods;
- which gradient estimator or approximation family to use for a given model.

The strongest source-safe statement is:

```text
AutoBayes defines the contract shape for local optimization semantics, but the
concrete optimizer registry is future implementation work.
```

It is not safe to say the paper provides a complete compiler, runtime, optimizer registry, or algorithm-selection system.

## Where Laxness Appears

Laxness appears in at least three places in the local research tower.

First, Bayesian lenses are exact-functorial under sequential composition, but parallel composition is lossy because local inversions see marginals rather than the full joint prior. The paper calls this lax monoidal behavior.

Second, statistical games preserve a chain rule for free energy, but tensor/parallel composition can carry information loss; with Shannon entropy, the laxness is measured by mutual information.

Third, in section 5, gradients compose into a structured local vector, but that vector is generally not strictly equal to the gradient of the composite global loss. The mismatch arises because local terms can depend on upstream parameters through pushed-forward priors and downstream posterior flow.

In Arcanum language, laxness means:

```text
the route can remain mechanically accountable even when strict equality,
complete information, or exact execution is unavailable.
```

But the warning is just as important:

```text
laxness is not permission for vague evidence.
```

AutoBayes uses laxness as a mathematical/accounting structure. If Arcanum borrows the word, it should mean a declared loss of strictness with a receipt, not hand-wavy tolerance.

## Arcanum Runtime-Semantics Analogy

Safe analogy:

```text
AutoBayes syntax/semantics split resembles Arcanum capability-contract/runtime
separation.
```

The useful mapping:

| AutoBayes | Arcanum reading |
| --- | --- |
| Open model | Declared composable surface |
| Bayesian lens | Forward behavior plus reverse handoff/inversion contract |
| Statistical game | Component plus local objective/evidence pressure |
| Parameter exposure | Explicit knobs the optimizer/runtime may act on |
| Semantics functor | Runtime interpretation that turns a declared structure into execution behavior |
| Lax section | Accountable mismatch between local execution data and strict global equivalence |

What the analogy may claim:

- A runtime should interpret a declared structure instead of rewriting the structure.
- Optimizable or executable handles should be explicitly exposed.
- Different runtime strategies may interpret the same declared route differently.
- Approximate execution should record where exact composition is lost.
- Local evidence/objective pressure should remain visible when joined into global synthesis.

What the analogy may not claim:

- Arcanum runtimes are automatically category-theoretic functors.
- Arcanum laxness has the same mathematical guarantees as AutoBayes laxness.
- AutoBayes proves anything about agent execution, task sessions, sigils, spells, or dispatch governance.
- "Semantics functor" should become canonical Arcanum vocabulary without a borrow/block/analogy-only decision.
- Any arbitrary runtime adapter is valid merely because it is "a semantics."

The disciplined Arcanum sentence is:

```text
AutoBayes gives a strong analogy for separating declaration from execution:
the route exposes local handles and a runtime semantics interprets them, with
any loss of strictness recorded as explicit laxness.
```

## Practical Design Implication For Arcanum

If this lane becomes useful for Arcanum, the candidate design object is not a single "semantics functor" abstraction. The safer design object is a runtime-semantics registry with receipts:

```text
declared route/capability
  -> exposed execution handles
  -> selected runtime semantics
  -> approximation or fallback notes
  -> receipt showing which local obligations joined cleanly
```

That registry would need to state:

- what the runtime is allowed to touch;
- what evidence it must return;
- whether it preserves the declared route exactly or approximately;
- what local/global mismatch is expected;
- what validation can detect unacceptable drift;
- whether a result is promotion-eligible, local-only, or analogy-only.

This is a design implication, not an AutoBayes source claim.
