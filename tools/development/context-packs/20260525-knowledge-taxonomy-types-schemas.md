Use this as a documentation pattern for `RUN.json`, `STATUS.json`, `RUNTIME-HANDOFF.md`, and adapter profile evidence. Do not import it as a dependency.

### E2: Small Enumerations

Source: `/tmp/knowledge-taxonomy/schema/v2.2.md:30-39`, `/tmp/knowledge-taxonomy/decisions/09-facet-value-enumeration.md:55-74`

Reusable idea:

- keep legal values inline where implementers look,
- validate controlled values strictly,
- allow `<unset>` only where the field tier permits it.

Fit for Arcanum:

Put runtime status, adapter status, validation grade, loop role, target kind, and adapter ids inline in the schema docs/templates. This is zero-overhead and prevents drift.

### E3: Typed Edge Catalog

Source: `/tmp/knowledge-taxonomy/schema/v2.2.md:71-88`, `/tmp/knowledge-taxonomy/docs/system-tagging-engine.md:64-78`

Reusable idea:

- hierarchy is a projection of typed edges, not a single parent tree,
- multiple hierarchy views can coexist.

Fit for Arcanum:

Use this for parent/child runtime runs and refinement loops:

- `parent_run_id`,
- `parent_loop_id`,
- `loop_role`,
- `stage_number`,
- optional future typed relationships such as `continues`, `repairs`, `spawned_by`, `candidate_of`.

Do not add a graph library now. Keep these as typed fields in JSON.

### E4: Authority Discipline

Source: `/tmp/knowledge-taxonomy/schema/v2.2.md:138-151`

Reusable idea:

- cross-references use stable ids rather than free text,
- external authority ids are explicit.

Fit for Arcanum:

Use stable local ids:

- `run_id`,
- `orchestrator_run_id`,
- `adapter_id`,
- `target_id`,
- `command_file`,
- `adapter_profile_path`.

Avoid free-text references when the runtime can point to a path or id.

### E5: Minimal Profile

Source: `/tmp/knowledge-taxonomy/schema/v2.2.md:153-164`

Reusable idea:

- a `minimal` profile is an honest triage signal, not under-modeling.

Fit for Arcanum:

Introduce no new machinery yet, but the pattern maps cleanly:

- `validation_grade=contract` is analogous to minimal viable runtime evidence,
- `validation_grade=adapter-safety` is stronger but still not execution proof,
- `validation_grade=execution` is the full proof.

No extra field is needed right now.

### E6: Throwaway Mechanical Validator

Source: `/tmp/knowledge-taxonomy/experiments/E8-mechanical-validator-vs-human-audit/README.md:18-31`, `:61-96`, `/tmp/knowledge-taxonomy/experiments/E8-mechanical-validator-vs-human-audit/validate.py:31-79`, `:82-128`

Reusable idea:

- use small mechanical validators to check schema-side conformance,
- treat them as bounded instruments, not permanent infrastructure,
- keep enumerations as simple sets.

Fit for Arcanum:

For runtime v1, prefer shell plus `jq` checks over adding a schema package:

- `jq empty`,
- `jq -e '.adapter_profile_path == "artifacts/adapter-profile.json"'`,
- enum checks with `jq -e 'IN(...)'` when needed,
- shell checks for symlink/shared-state safety.

### E7: System-Generated Tagging With Audit Trace

Source: `/tmp/knowledge-taxonomy/docs/system-tagging-engine.md:14-20`, `:24-50`, `:52-62`

Reusable idea:

- labels are not enough; record rule/evidence trace,
- human judgment governs rule changes rather than being the tagging source.

Fit for Arcanum:

Adapter status should remain generated by the runner/adapter and recorded with evidence:

- raw condition,
- classifier/status mapping,
- blocked reason,
- output paths,
- validation grade.

Do not ask humans to manually assign runtime status except as a later review override.

### E8: Honest Scope Boundary

Source: `/tmp/knowledge-taxonomy/verdict.md:33-45`, `:150-175`, `:242-264`

Reusable idea:

- the schema is useful because it names its scope and failure modes,
- cross-frame review found non-overlapping classes of flaw.

Fit for Arcanum:

Do not try to make the runtime schema a universal ontology. Keep it to durable execution facts:

- run identity,
- handoff,
- status,
- adapter profile,
- event log,
- result,
- parent/child topology.

Leave semantic interpretation to refine/task-session/invoke.

## Recommended Use Without Overhead

Copy patterns, not infrastructure.

Adopt now:

- inline enum lists in runtime docs and templates,
- required/recommended/optional field tiers,
- stable ids/paths instead of free-text references,
- provenance fields for generated evidence,
- validation grades as lightweight profile levels,
- small `jq`/shell validation checks.

Do not adopt now:

- taxonomy repo dependency,
- graph database,
- YAML frontmatter parser dependency,
- broad tagging engine,
- generic ontology layer for runtime state.

## Direct Runtime Schema Suggestions

Add or preserve these v1 fields:

```json
{
  "schema_version": "arcanum.runtime.run.v1",
  "run_id": "runtime-run-id",
  "adapter_id": "codex-exec",
  "adapter_profile_path": "artifacts/adapter-profile.json",
  "target_kind": "command|skill|task|swu|stage|manual",
  "loop_role": "root|stage|candidate|nested|repair|continuation"
}
```

Keep these enums inline in docs/templates:

```text
status: queued | running | passed | flagged | blocked | failed
adapter_status: not-started | running | passed | flagged | blocked | failed
validation_grade: contract | adapter-safety | execution | null
target_kind: command | skill | task | swu | stage | manual
loop_role: root | stage | candidate | nested | repair | continuation
```

## Gaps

- The repository provides Markdown schema specs and validator examples, not importable TypeScript/Python runtime schemas.
- `schema/v2.2.md` is candidate status; do not treat it as canonical for Arcanum.
- The validator uses Python dependencies (`frontmatter`, `pandas`); do not copy that dependency surface for runtime v1.

## Verdict

Use `knowledge-taxonomy` as a schema-design precedent, not a runtime dependency.

The best low-overhead adoption is documentation and validation discipline:

- explicit field tiers,
- inline enums,
- stable ids,
- provenance,
- minimal/contract-level evidence,
- small mechanical validators.
