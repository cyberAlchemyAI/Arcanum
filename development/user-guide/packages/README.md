## Boundary Rule

Invoke authored these packages as planning artifacts. It did not promote any sigil, install any command, mutate registries, or create durable user profile state.

## Work Rule

Work one package at a time:

1. Use the package `WORK-PACK.md`.
2. Execute the first ready task or SWU through `task-session` or the named lifecycle owner.
3. Validate the package before moving to the next package.
4. Preserve User local memory boundaries throughout.
