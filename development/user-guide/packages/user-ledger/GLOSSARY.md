# User Ledger Glossary

| Term | Status | Meaning |
| --- | --- | --- |
| user-ledger | candidate | Protected local ledger for learning preferences, concept states, receipts, and user glossary evidence. |
| domain anchor | candidate | A source domain the user can use to understand another target domain. |
| vocabulary preference | candidate | A preferred, avoided, aliased, or style-specific language note. |
| concept state | candidate | Evidence-backed status for a concept, such as exposed, clarified, practiced, transferable, mastered, or stale. |
| mastery evidence | candidate | Active evidence that the user can recall, explain, transfer, or contrast a concept. |
| receipt | candidate | Bounded output from another capability proposing a ledger update. |
| residue | candidate | Learning friction, failed analogy, unresolved confusion, or open question. |
| visibility rule | candidate | Rule describing what can be stored, shown, exported, reset, or promoted. |

## Glossary Consistency

This glossary is user-ledger-local. It does not promote canonical Arcanum definitions.
