# Stage 03: Interrogation Refine Review

Status: `flag`

## Findings

| Severity | Finding | Resolution |
| --- | --- | --- |
| P1 | User learning memory can become too broad if it tracks every interaction. | Limit the first ledger to Guide receipts, vocabulary preferences, prior-domain bridges, blockers, and confirmed mastery evidence. |
| P1 | Clarification count can be misread as user ability. | Treat count as interaction friction, not intelligence or skill. Store it only with concept, context, strategy, and evidence. |
| P1 | A user glossary can drift from canonical definitions. | Split user-local mastery records from Inventory/Ontology definitions. |
| P2 | Guide may overfit to one analogy family and prevent generalization. | Require concept ladders: specific example, bridge analogy, target-domain definition, abstraction, transfer prompt. |
| P2 | The install game could become a barrier. | Make it optional, short, replayable, and useful even when skipped. |
| P2 | Cross-domain explanation can flatten the target domain. | Require each analogy to name what maps, what does not map, and what the target concept really is. |

## Dialectic

| Role | Position |
| --- | --- |
| Personalization advocate | Store enough evidence to adapt the next explanation. |
| Privacy steward | Store the minimum local learning record and never infer sensitive traits. |
| Learning scientist | Require retrieval, self-explanation, transfer, and scaffolding/fading rather than only satisfaction signals. |
| Arcanum owner-boundary reviewer | Keep User/Guide evidence out of canonical registries until separate promotion. |

## Convergence Criteria

- First unit must be ledger and receipt contract, not the whole Guide experience.
- User memory must be local, reviewable, and separate from canonical knowledge.
- Mastery must require active evidence, not passive agreement.

## Verdict

Proceed, with flags. The target is valuable but must be privacy-minimal and evidence-backed.
