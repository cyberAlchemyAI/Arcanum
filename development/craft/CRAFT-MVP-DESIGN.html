Authority Boundary

The MVP stays in development/craft/. It does not promote Craft into a canonical registry entry, sigil, spell, or command.

Operational Shape

The ledger tracks lifecycle state, owned artifacts, gates, blockers, enablers, relations, and decisions as inspectable Markdown rows.

Side Thread

Runtime and refine-orchestrator work remains linked context only. It is not an acceptance criterion for this MVP.

Deferred Growth

Scoring, generated indexes, and role delegation become candidates only after the file-backed ledger passes validation.

Workflow

The architecture is deliberately boring in the useful way: define the source, instantiate the ledger, prove the blocker rule, validate, then sync package state.

Decision Flow

These are the architecture gates that keep the MVP from drifting into runtime or pretending a raw blocker is resolved.

ContinueRow fits YAML schemaUse the existing fields and keep executing the task.
StopRow needs a new required fieldRun compact /refine on CRAFT-LEDGER-SCHEMA.yml before continuing.
BlockRaw blocker lacks refinementDo not mark it resolved.
WaiveBypass normal refinementRequire a linked decision row with decision_type = waiver.
ReviewValidator or auditor lane involvedRequire evidence notes before closure.
DeferRuntime, scoring, or delegation appearsRecord as out of scope unless a new plan is opened.

Blocker Gate

The blocker rule is the heart of this MVP: false closure is worse than visible friction.

Allowed lifecycle
raw>typed>refined>resolution_proposed>resolved
Blocked shortcut
raw>resolvedtyped > resolved
Waiver path
raw or typed>waiver decision>waived

Operational Lanes

Types explain what kind of condition exists. Lanes explain what kind of responsibility is needed. Roles remain advisory until later automation.

businessMeaning and valueScope, acceptance, priorities, and trade-off decisions.
techStructure and feasibilitySchema, interfaces, integration, and recomposition.
qaTest readinessCoverage, defect confirmation, and regression safety.
validatorEvidence acceptanceIndependent check that a gate is satisfied.
auditorTrace and governanceDecision provenance, waiver evidence, and process conformance.

Execution Handoff

The architecture is ready for the first bounded execution task. The first task should create the actual ledger fixture; validation comes after the blocker lifecycle rows exist.
