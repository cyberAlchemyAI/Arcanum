Craft as a way of making with LLMs

When an LLM makes something, Craft asks what got translated.

Craft treats LLM execution as a making process: you bring an intention, choose a shape for it, let a probabilistic translator produce an artifact, then inspect what was preserved, what drifted, and what still needs repair.

The Basic View

Craft starts before the prompt and ends after the output.

A prompt is only one visible part of the operation. The real craft operation includes the intention behind the prompt, the schema that frames the work, the context and tools handed to the model, the artifact it produces, and the validation that tells us whether the result actually fits.

  • The LLM is not treated as a deterministic compiler.
  • The output is not treated as self-proving.
  • Residue is not treated as noise; it is evidence about the translation.

The practical question

Did the artifact preserve enough of the intended structure to be useful, reviewable, and recomposable into the larger work?

How An LLM Execution Looks In Craft

The model translates, it does not simply obey.

F_PCRA(I, S, context, tools) -> D

The LLM-centered process turns intention and schema into an artifact using the context and tools it can see.

Uncertainty has sources.

E = entropy(F_PCRA, S, context, relation_load, unit_size)

Entropy names the pressure created by ambiguity, context load, relation load, and oversized or underspecified work units.

The output has to answer back.

V(S, D, G) -> R

Validation compares what got made back to the schema, under the rules and ownership of the current craft space.

Craft reads the remainder.

If the residue is acceptable, the work can close. If it is repairable, improve the schema, context, translator setup, or artifact inside the same layer.

The Making Flow

Shape the intention

Give the work a schema: a spec, plan, contract, prompt frame, examples, or validation target.

->

Run the translator

Let the LLM-centered process produce the artifact using selected context, tools, and local vocabulary.

->

Read the fit

Validate the result, then look at residue to understand what the translation preserved or lost.

Vocabulary In Plain Language

Everyday view I ask the model to make something.
Craft view I set up a translation from intention into artifact, then inspect the residue left by that translation.
I

Intention

What you are trying to make real: the purpose, pressure, desired change, and next artifact you want to exist.

S

Schema

The shape you give the intention so the model can work with it: a spec, plan, task, taxonomy, constitution, interface, example set, or method contract.

F

Translator

The full process that turns schema into artifact. It includes the LLM, prompt frame, selected context, tools, local vocabulary, harness, validation, and feedback.

PCRA

LLM Translation Behavior

The model is probabilistic, contextual, relational, and attentive. It responds to what is likely, what is present, what is related, and what its attention can hold.

E

Entropy

The uncertainty pressure in the run: too many plausible paths, unstable terms, noisy context, too many relations, or a work unit that is too large or too small.

D

Artifact

What the operation actually produces: code, document, design, validation evidence, telemetry, task result, runtime behavior, or another concrete output.

R

Residue

The meaningful remainder after the output exists: drift, missing structure, ambiguity, contradiction, scope pressure, or a validation gap.

G

Governance

The rules for the work: what counts as valid, who owns the next move, which route should handle it, and what is allowed to become canonical.

V

Validation

The act of checking the artifact against the schema and the local rules, so the output has to prove its fit instead of merely looking plausible.

SCU

Smallest Coherent Unit

The smallest work unit that still makes sense. It has one responsibility, enough context, clear inputs and outputs, a local check, and a path back into the larger work.

Why Craft Cares About Unit Size

choose SCU such that: meaning(SCU) is sufficient responsibility(SCU) is singular relation_load(SCU) is bounded validation(SCU) is local recomposition(SCU -> upper schema) is explicit

Too Small

The model can do the tiny piece, but the piece no longer carries enough meaning to rejoin the whole cleanly.

SCU

The unit is small enough for attention, but still meaningful enough to validate and recompose.

Too Large

The model has to preserve too many relations at once, so attention loss and relation drift become more likely.

How Craft Reads A Bad Or Weird Output

  • Missing details: the schema or context did not say enough.
  • Attention loss: the work unit may be too broad or the context too noisy.
  • Relation drift: the important relationships were implied when they needed to be declared.
  • Recomposition failure: the piece works locally but does not reconnect to the larger artifact.
