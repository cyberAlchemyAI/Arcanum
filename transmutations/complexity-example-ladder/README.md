# Complexity Example Ladder

Complexity Example Ladder is a Transmutation sigil that turns one bounded
explanation or comparison into aligned low-, medium-, and complex examples.

It exists because an abstract explanation can be technically complete and still
leave the reader unable to see how the idea behaves. The ladder holds one concept
or scenario invariant while adding structural complexity in controlled steps.

## Use When

- a user asks for an example, illustration, or deeper explanation,
- a caller requires examples calibrated by complexity,
- several options need a fair comparison under the same conditions,
- a concept becomes ambiguous when identity, state, dependencies, or boundaries
  interact.

## Do Not Use When

- a factual answer needs no example,
- a deterministic fixture already answers the question,
- source evidence is too weak to ground or safely label a hypothetical,
- the caller is trying to use an example as permission, proof, or a decision.

## Complexity Contract

Every meaningful invocation produces all three rungs:

- **Low:** one primary concept or action in a local, consequence-light scenario.
- **Medium:** multiple interacting concepts or options with at least one dependency,
  state change, or boundary.
- **Complex:** several actors, layers, states, or dependencies plus an exception,
  uncertainty, failure path, authority boundary, or dependent decision.

Complexity is structural. Extra words, jargon, or renamed objects do not make a
scenario more complex.

In comparative mode, every rung uses one shared scenario and gives every admissible
action option equivalent coverage. Defer and stop are shown only as continuation
states; the sigil does not invent product behavior for them.

## Authority Boundary

The ladder is explanatory evidence only. It cannot establish admissibility, select
an option, satisfy an owner gate, change a decision result, or authorize mutation.
Hypothetical details are labeled, and every output states what its examples do not
prove.

## Output

The sigil returns the subject, complexity basis, evidence and assumptions, aligned
low/medium/complex examples, coverage checks, unsupported claims, and an explicit
`decision effect: none` statement.

## Why This Is a Transmutation

The work needs interpretation and structured judgment, so it is not a deterministic
Formulae check. It is also one bounded synthesis with no persistent gate or recursive
orchestration, so Arcana would add unjustified authority and cost.

## Lifecycle

The reusable contract is validated through the colocated `development/` experiment
harness. Promotion remains on hold until real low-, medium-, and complex output
bodies pass contract review.
